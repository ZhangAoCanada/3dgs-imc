## Acceptance and completion

Train for 30,000 iterations. Freshly render every prescribed test view from the
final saved model. Accept only if the **same model** satisfies all of:

- SSIM ≤ its reference SSIM;
- PSNR ≤ its reference PSNR;
- LPIPS ≥ its reference LPIPS.

Use unrounded original per-scene exported triples for Tables I/II, and the available
paper scene triples for Table III. Comparisons are strict inequalities as written,
without a hidden tolerance. All per-view values must be finite and the camera list
must match the complete prescribed split. A technical failure cannot qualify.

Start at seed 0 and cycle through unfinished configurations, incrementing each
configuration’s seed after a complete nonqualifying run. Keep hyperparameters and
metric implementation fixed. Select the first qualifying attempt and retain all
others, including failures. There is no fixed attempt cap, as requested; stochastic
variation does not guarantee that every threshold will eventually be reached.

Completion requires **67 selected final checkpoints**, required method sidecars,
fresh metrics, and SHA-256-verified copies on the main host. Launching the queue
is not completion. `status.json`, `attempts.jsonl`, and `selected.json` distinguish
running, rejected, failed, and accepted attempts. A selected result includes both
execution and mirror hosts, configuration, seed, reference triple, measured triple,
checkpoint path, and checksum. Do not replace the missing-original identities with
these new checkpoint identities.

## Frozen execution recipe

Use one available physical GPU 0 or 1 per process on `hust2`, selected through
`CUDA_VISIBLE_DEVICES`. Retain original environments and repositories. Execute
isolated snapshots in `code/{3dgs,pgsr,mcmc,scaffold}`; each contains native source
hashes and a `campaign.patch` documenting the adaptations. PGSR additionally
records `data-isolation.patch`, redirecting its native PLY regeneration to each
run’s cache while preserving the regenerated bytes. Full parsed arguments
are saved beside every model. Seeds are passed explicitly to Python, NumPy and Torch.

Use surviving historical launcher options and capacities, with frozen current
native defaults for other fields. Original full configurations and seeds remain
unknown. The eight aerial entries are reconstructed recipes. A commented MCMC
launcher supplies MatrixCity’s 7M and Zeche’s 2M caps; this is launcher evidence,
not proof of the missing original checkpoint settings. PGSR aerial uses its native
6M capacity because the original capacity is unknown.

Images are decoded once and saved losslessly as PNG content under their original
COLMAP filenames. This prevents method environments’ JPEG libraries from changing
the pixel inputs. Original data is untouched. Main-host Mip, TNT and aerial data
are used; Mill 19 uses `hust2:/data1/zhangao/DATA-small/*/images_4`, including
sci-art’s original 1215×911 images. Each dataset records source bytes, frozen bytes,
decoded pixel hashes, dimensions, decoder version, and copied geometry hashes.
The saved split files are copied unchanged. Resolution is 1.

The MCMC rasterizer is the already isolated main-host 3σ implementation compiled
for the remote environment in the [five-candidate verification](../mcmc-candidate-verification-2026-09-27/REPORT.md).
The native installed extension is unchanged. Other methods use their native extensions.

The campaign renders test RGB directly with each method’s native Gaussian renderer.
It excludes the current 3DGS CLI’s unrelated super-resolution processing and
Scaffold’s automatic GPU override. PGSR test rendering uses native RGB without
an appearance model, matching its test renderer; its appearance sidecar is retained.
Scaffold’s separate test-camera IDs can exceed the training embedding count, so
all test views use the mean learned training appearance embedding. This is an
explicit reconstruction choice, fixed across all seeds, without fitting test pixels.
Scaffold’s native optimizer capture references a missing `_local` member; the
campaign saves its actual optimizer state separately from the full PLY/MLP model.

Metrics use the common native SSIM and PSNR calls and LPIPS VGG 0.1, RGB PNG
quantization, and float32 arithmetic means over the complete test split. Each
attempt retains rendered images, GT, camera mapping, aggregate/per-view metrics,
logs, full settings, optimizer state, and the model with all neural sidecars.

## Operation

[scripts/coordinator.py](scripts/coordinator.py) runs on the main host, launches
[scripts/run_one.py](scripts/run_one.py) remotely, mirrors each terminal attempt,
verifies hashes, and applies the acceptance condition. It holds an exclusive lock
and records its PID and current attempt. It never deletes an attempt or modifies
an original model. Unknown technical failures block the affected configuration
for inspection while other configurations continue.

A 60 GiB free-space guard on each host pauses new attempts before exhaustion.
Insufficient storage is a paused queue, not a completed result. The optional
`STOP_AFTER_CURRENT` file stops the coordinator after its current attempt.
Read `status.json` and the PID/process before restarting; a surviving remote job
must not be duplicated. Smoke tests use separate directories and never count
toward the 67 results.
